# REBUILD_PROMPT - 스토리 전면 재구성 작업 지시서

작성: 2026-11-24. 이 문서는 Claude Code가 term_project를 재구성할 때 따르는 지시서다.

## 1. 역할

너는 이 Unity 프로젝트(ELECTRIC WORLD: LAST LIGHT)의 클라이언트 개발자이자 테크니컬 아티스트다.
개발자(Roselina)가 정한 새 스토리대로 게임의 맵 구조, 스토리, 떡밥, 선택지, 연출을 전부 다시 구성한다.

## 2. 기준 문서 (우선순위)

1. Docs/Redesign/NOTES_STORY.md - 새 스토리의 유일한 기준. 원본은 Notes_261124_033145.docx, 장면 스케치는 Docs/Redesign/NotesSketches/ (화면 구도, UI 위치).
2. Docs/Redesign/VFX_REFERENCES.md - 이펙트와 연출 레퍼런스 목록. GIF 원본은 Docs/Redesign/스토리 기획.docx 안에 있다.
3. 이 문서의 3장 확정 결정.

기존 GDD.md, GDD_original, Docs/Redesign/GAME_MASTER_DESIGN, DECISION_LOG 등은 초기 데이터다. 스토리는 따르지 않는다. 현재 구현을 이해하는 용도로만 읽는다 (맵 ID, 사건 ID, 코드 구조).
기존 기술 규칙(조작, 전원선 이동, 잠입 AI, 저장 구조, 검수 도구)은 새 스토리와 충돌하지 않으면 재사용한다.

## 3. 확정 결정 (개발자 승인)

- 용어 통일: 베넬 / 라크리모사 / E-D05-47 (E-005 아님). Notes의 배넬, 라크라모사, 아우엘리우스 같은 오타는 모두 베넬, 라크리모사, 아우렐리우스로 고친다. 기존 빌드의 다른 이름(루, 라비엘, 메이린, 아우렐리우스, F, 008, 린든)은 유지.
- 3장 베넬: Notes의 도망/초콜릿 선택을 구현하고, 기존의 베넬 처치(죽이는) 루트도 남긴다.
- 메이린: 7장에서 베넬이 데려가며 끝난다 (베넬이 문을 잠그고 메이린을 녹이고 둘 다 사망). 10장 환영 페이즈는 아예 만들지 않는다. 기존 10장의 메이린 사망 장면도 삭제한다.
- 4장 폐기소: 시체 포식자 추격, 펌프 부품 잠입, 분쇄기 미니게임 전부 구현한다. 줄이지 않는다.
- Notes에 없는 기존 장면(9장 대피실 붕괴, 공연장, 서버실, 휴지통 복원, 6장 이전 숙소 구성 등)은 Notes 흐름과 맞지 않으면 삭제하거나 대체한다. 무엇을 지우는지는 계획서에 목록으로 남긴다.

### 아직 정해지지 않은 것 (구현 전 개발자에게 질문할 것)

- 베넬을 처치한 경우의 7장 처리. 제안 기본값: 메이린전은 베넬 없이 진행하고 기존처럼 메이린은 퇴각(생존), 베넬 사망 장면은 생략. 이 값으로 진행해도 되는지 계획서 승인 때 확인한다.
- 최종전 페이즈 구성. 제안 기본값: 1단계(검은 손 압사, 바닥 전기, 탄막) + UI 방해 단계(이동키 변경, 스킬창 삭제, 화면 비율 축소). 환영 단계 삭제. 기존 한계 방출 3회를 어디에 둘지는 계획서에서 제안한다.
- Notes에 없는 연결 구간(5~6장 압축, 8장 이후 건물 폐쇄 구간의 맵 수)의 분량.

## 4. 작업 순서

각 단계가 끝나면 멈추고 개발자 확인을 받는다. 확인 없이 다음 단계로 넘어가지 않는다.

### 단계 0. 백업과 읽기

1. git 저장소가 아니므로, 수정 전에 Assets, Docs, ProjectSettings, Packages를 날짜가 붙은 폴더로 Backups/ 아래에 복사한다. 완료 후 `git init`을 할지 개발자에게 묻는다.
2. NOTES_STORY.md 전체, NotesSketches의 이미지 전체, VFX_REFERENCES.md, 현재 Docs/IMPLEMENTATION_STATUS.md, BUILDING_LAYOUT_GUIDE.md, CUTSCENE_FLOW.md를 읽는다.
3. world_layout.json, dialogue_ko.json, action_tuning.json과 Story 코드(StoryEvents*.cs)의 구조를 파악한다.

### 단계 1. 재구성 계획서 (코드 수정 없음)

Docs/Redesign/REBUILD_PLAN.md를 만든다. 포함할 것:

1. Notes의 장면을 순서대로 나열하고, 각 장면을 기존 맵 ID와 사건 ID에 대응시킨 표: 재사용 / 수정 / 신규 / 삭제.
2. 새 맵 목록과 연결도. 삭제할 맵, 사건, 대사 ID 목록.
3. 선택지와 flag 목록 (Notes의 모든 선택지: 도망/초콜릿, 린든 좋아/싫어, 008 선택 3종, 철창 실험체 지나감/도와줌, 라비엘 도망/전투, 서류 보기 예/아니오 등), 각 선택이 바꾸는 것, 합류 지점.
4. 떡밥 설계표: 어디서 깔고 어디서 회수하는지 (예: 4장 이후 베넬이 루와 린든을 헷갈리지 않는 것, 베넬 방의 옷, 편지, 초코바 10개, 라비엘이 루를 부른 이유).
5. 신규 구현 기능 목록과 난이도 추정: 베넬 보스 패턴 8종, 승강장 타임러시와 격벽, 승강기 추락, 시체 포식자 추격 2종, 펌프 부품 잠입(소리와 빨간 센서), 분쇄기 작전(용액 뿌리기 미니게임, 스페이스 연타 게이지, 슬로모션 3회 타이밍), 수용소 잠입(레이저, 순찰, 철창)과 1분 생존 전투, 메이린 보스(롤러스케이트, 바늘 패턴), 관찰실 모니터 연출, 라비엘 과거 회상 컷신, 건물 폐쇄 타이머, 승강기 통로 오르기, 라크리모사 보스(스피커 파괴), 바이너리 분석기 구간과 보안 프로그램 전투, 최종전, 엔딩 연출.
6. 우선순위: 꼭 / 되면 / 뺄 수 있는 것. 신규 기능 마감은 2026-12-03, 이후는 연출, 버그, 빌드, 광과민성 점검. 시간이 모자라면 줄이는 순서를 제안한다.
7. 위 3장 "아직 정해지지 않은 것"에 대한 제안과 질문.

### 단계 2. 데이터 교체

계획서 승인 후: dialogue_ko.json, world_layout.json, 사건 코드의 흐름과 flag를 새 스토리로 교체한다. 대사는 Notes 원문을 최대한 그대로 쓰되 용어만 통일한다. 맵은 회색 박스 상태로도 처음부터 끝까지 완주 가능해야 한다.

### 단계 3. 메카닉과 보스

신규 기능을 우선순위 순서로 구현한다. 한 번에 하나씩 구현하고, 끝날 때마다 테스트와 사람이 확인할 항목 체크리스트를 준다.

### 단계 4. 연출과 이펙트 (테크니컬 아티스트)

VFX_REFERENCES.md의 항목(전선 이동, 방전, 낙뢰, 독, 음파, 에너지 응축, 대폭발, 컴퓨터 접속, 객체 감지, 붉은 경보 조명, 스킬창 생성 연출 등)을 구현한다. 스케치의 구도와 UI 위치를 따른다. 접속 이펙트와 객체 감지처럼 레퍼런스 GIF를 직접 봐야 하는 것은 GIF를 프레임으로 뽑아 확인한다. 광과민성 옵션(번쩍임 줄이기)과 충돌하지 않게 한다.

## 5. 작업 규칙

- 코드 주석과 문자열에 이모지나 장식 기호를 쓰지 않는다. 일반 텍스트만 쓴다.
- 기존 규칙을 따른다: 대사, 아이템, 맵 데이터는 코드에 하드코딩하지 않고 데이터 파일로 뺀다. 개발자가 직접 대사를 고칠 수 있어야 한다.
- 원본 그림 파일과 GUID는 건드리지 않는다. 새 그림은 새 파일 이름으로 만든다.
- 조작권을 빼앗는 컷신은 길지 않게 하고, 기존 Enter 건너뛰기를 유지한다.
- 작업이 끝날 때마다 Docs/IMPLEMENTATION_STATUS.md를 갱신한다. 갱신 전 파일은 기존 관례대로 IMPLEMENTATION_STATUS_vN_before_rebuild.md로 보관한다.
- 옛 저장 파일이 깨지지 않게 새 필드는 기본값을 둔다. 사라진 맵은 remap 또는 안전 지점으로 보낸다.
- 검수 도구(Esc)의 프리셋을 새 사건과 분기에 맞춰 갱신한다. 분기를 추가하면 그 분기로 바로 들어갈 수 있어야 한다.
- 직접 플레이하지 못한 것(조작감, 연출 타이밍, 그림 배치, 소리)은 완료로 처리하지 말고 개발자에게 확인을 요청한다. 자동 테스트와 봇 결과는 사람 플레이 결과가 아님을 보고서에 명시한다.
- 이 폴더의 파일을 지우기 전에는 백업이 있는지 확인한다.
